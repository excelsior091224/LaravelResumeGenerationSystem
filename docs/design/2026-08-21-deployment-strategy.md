# 2026-08-21 本番環境デプロイ戦略検討

## 1. 前提条件

- 個人開発だが、独自ドメイン + Googleアドセンスによる収益化を検討
- 開発はDocker環境で行っている
- `vendor`ディレクトリを直接アップロードすればcomposerは必須ではないが、SSHは必須
- 既にGoogle Cloudのアカウントを保有しており、GCE無料インスタンスの利用も選択肢に入る

## 2. サーバー環境の比較

| サーバー環境                              | 月額費用       | 割り当てスペック       | Docker/SSH対応                      | メリット・デメリット                                                                            |
| ----------------------------------------- | -------------- | ---------------------- | ----------------------------------- | ----------------------------------------------------------------------------------------------- |
| GCE (無料枠 e2-micro)                     | 0円            | vCPU×1, メモリ1GB      | ◯（SSH可）                          | 費用は最強だが、メモリ不足でDockerやLaravelが頻繁に落ちる。転送料の従量課金・レイテンシにも注意 |
| 国内クラウドVPS（ConoHa / シン・VPSなど） | 約500〜1,000円 | vCPU×2, メモリ1GB〜2GB | ◯（Docker公式テンプレートあり）     | 定額で安定。Dockerが快適に動き、転送量も実質無制限                                              |
| 共用サーバー（エックスサーバー等）        | 約1,000円      | 他ユーザーと共有       | ×（Dockerは不可、手動デプロイのみ） | 表示速度は最速でアドセンス審査・SEOに有利だが、Docker運用は諦める必要あり                       |

### GCE無料枠の注意点

- **メモリ不足**: 1GBではLinux OS + Dockerデーモン + MySQL/PHP-FPM + Nginxを同時稼働させるとOOMで頻繁にクラッシュする。Swap設定でしのげるが動作は重い
- **ネットワーク転送料**: 無料枠は米国リージョンからの下り転送が月1GBまでと限定的。アドセンスでアクセスが増えると従量課金が発生しうる
- **レイテンシ**: 無料枠維持には米国リージョン（オレゴン・アイオワ等）が必要で、日本向けサイトには100〜200ms程度の追加レイテンシが乗る。Core Web Vitals（LCP等）はSEO・アドセンス双方に影響するため軽視できない

### 結論

完全無料に挑戦する実験目的ならGCE無料枠、収益化を本気で目指すなら**国内VPS**が妥当。

## 3. データベース: MySQL → SQLite移行時の管理ツール

SQLiteは単一ファイルのため、MySQLの「phpMyAdmin」のようなWebブラウザ型ツールは一般的でない。ローカルPCにGUIツールを入れ、SSHトンネル経由でVPS上のファイルを直接参照する運用が安全かつ一般的。

### 候補ツール

- **DBeaver**: 無料でSQLite/MySQL両対応。移行期間中に両方を触るなら最も無難
- **TablePlus**: UIがモダンで使いやすい（無料枠あり）
- **SQLiteStudio**: SQLite専用の軽量な無料ツール

個人開発規模であればGUIツールに頼らず、必要な時だけSSH経由で`php artisan tinker`や`sqlite3`コマンドを叩く運用でも十分。

### 注意点

SQLiteは複数プロセスからの同時書き込みに弱く、`database is locked`が発生しうる。低トラフィックなら問題ないが、アクセス急増に備えて`PRAGMA journal_mode=WAL;`でWALモードを有効にしておくことを推奨。

## 4. さくらインターネット不正アクセス問題（2026年8月中旬発生）の影響検討

### 事案の要点

- 被害箇所: 「さくらのレンタルサーバ」共用環境（583アカウントへの不正ログイン・マルウェア設置）、および同社「販売管理システム」（約136万件の会員情報漏えいの可能性）
- 影響を受けないサービス: 公式発表通り、「さくらのVPS」のハイパーバイザ（仮想化基盤）への侵入・影響は確認されていない

### VPS利用時のリスク評価

技術的には、VPSは「OS丸ごと独立した仮想環境」のため、共用レンタルサーバーのような他アカウントの侵害の影響は受けない構造。ただし以下の運用・管理面のリスクに注意が必要。

1. **会員パスワード漏えいリスク**: 販売管理システムへの不正アクセスにより、ハッシュ化されたパスワード情報へのアクセス可能性が判明。他サイトとパスワードを使い回している場合、リスト型攻撃の二次被害の恐れ
2. **フィッシングメール増加**: 会員情報（氏名、メールアドレス、契約情報等）が閲覧された可能性があり、さくらを騙った偽メールのリスクが上昇

### 対策

- さくらの会員メニューパスワードは固有のものにし、2要素認証（MFA）を必ず設定
- メール内リンクを安易に踏まず、公式サイトのブックマークからログインしてアナウンスを確認

### 追加考慮点（技術面以外）

- インシデント対応でサポート部門が逼迫しており、契約直後のトラブルシューティングで返信が遅くなる可能性
- 今後調査が進み被害範囲が拡大する可能性もゼロではないため、情報が出揃うまで数週間様子を見るのも合理的な判断

## 5. 総合推奨

優先順位:

1. **ConoHa VPS**（月額650円〜）: Docker公式テンプレートが用意されており、要件（Docker運用・独自ドメイン・SSH必須・composerレス運用も可）に最も素直にフィットする
2. **シン・VPS**: コスパ重視の有力候補。ただしDocker公式テンプレートの有無は個別確認が必要
3. **さくらのVPS**: 技術的な安全性に問題はないが、直近のインシデントで心理的抵抗があるなら無理に選ぶ必要はない

SQLite移行は個人開発・低〜中トラフィックの収益化フェーズであれば十分実用的。WALモードの有効化を忘れないこと。
